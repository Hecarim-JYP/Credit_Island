### 0.3 기술 단순화

- **ES Modules 대신 일반 `<script>` 태그**로 파일 몇 개를 불러온다. 서버 없이 `index.html`을 더블클릭해도 열린다(심사 환경 대비).
- 문제 데이터도 JSON이 아니라 JS 파일로 둔다. `file://`에서는 `fetch`가 막히기 때문이다.
- 그래픽은 이미지 파일 없이 캔버스 도형과 이모지로 그린다.
- 문제는 **생성기**로 만든다. 수학은 연산 규칙으로, 영어는 단어 목록에서 "뜻 고르기" 문제를 만든다. 손으로 쓰는 문제를 최소화한다.

## 1. 개요

| 항목 | 내용 |
|---|---|
| 장르 | 탑다운 탐험 + 퀴즈 배틀 RPG |
| 한 줄 소개 | 과목(스테이지)을 탐험하며 강의(몬스터)를 퀴즈로 이겨 이수하고, 캐릭터를 키워 졸업하는 게임 |
| 레퍼런스 | 포켓몬 골드 버전의 **탐험 → 조우 → 턴제 배틀 → 성장** 구조만 참고한다. 이름, 캐릭터, 그래픽, 음악, 대사는 전부 새로 만든다 |
| 플랫폼 | 웹 브라우저 (PC와 모바일, 우선순위는 §17에서 결정) |
| 기술 | Vanilla JS(ES Modules) + Canvas 2D(월드) + DOM(텍스트 UI), 빌드 도구 없음 |

### 1.1 컨셉

플레이어는 신입생이다. 캠퍼스(허브)에서 과목관에 들어가면 그 과목을 테마로 한 필드가 펼쳐진다. 필드에는 **강의**가 몬스터처럼 돌아다닌다. 강의는 배우는 개념을 형상화한 존재다(예: 분수 슬라임, 방정식 골렘, 관계대명사 유령). 강의와 마주치면 퀴즈 배틀이 시작된다. 정답이 공격이고 오답은 피격이다. 한 과목의 강의를 순서대로 모두 이수하고 마지막 **기말고사**(보스)를 통과하면 그 과목을 이수한다. 모든 과목을 이수하면 졸업 엔딩이다.

### 1.2 용어 대응표

| RPG 개념 | 이 게임 |
|---|---|
| 월드 / 허브 | 캠퍼스 |
| 스테이지 | 과목 |
| 일반 몬스터 | 강의 |
| 보스 | 기말고사 |
| 랜덤 조우 | 복습 퀴즈 |
| 몬스터 HP | 진도 (0%에서 100%로 채우면 이수) |
| 플레이어 HP | 집중력 |
| 공격 | 정답 |
| 피격 | 오답, 시간 초과 |
| 화폐 | 장학금 |
| 상점 | 매점 |
| 도감 | 성적표 |
| 세이브 포인트 | 휴게실(스테이지 안), 기숙사(캠퍼스) |
| 풀숲 | 책더미 (복습 퀴즈가 나오는 타일) |

몬스터 HP를 깎는 대신 **진도를 채우는** 방식으로 표현한다. 강의를 "쓰러뜨리는" 게 아니라 "끝까지 듣는" 것이라 테마와 맞는다.

## 2. 설계 원칙

검토 과정에서 정한 원칙이다. 이후 모든 시스템은 이 원칙을 따른다.

1. **정답 여부는 오직 플레이어의 실력으로 정해진다.** 캐릭터 능력치는 정답을 대신 맞혀 주지 않는다. 능력치가 바꾸는 것은 여유(몇 번까지 틀려도 되는가, 시간이 얼마나 있는가)와 효율(몇 문제를 맞혀야 이수하는가)뿐이다. 그래야 레벨업이 의미 있으면서도 학습 가치가 남는다.
2. **문제만 내면 시험이지 학습이 아니다.** 모든 문제에 해설을 붙이고, 강의 시작 전 개념 카드를 보여 주고, 틀린 문제는 오답노트로 다시 풀게 한다.
3. **아이템은 확실히 쓸모 있게, 대신 개수로 조절한다.** 패스는 정답으로 처리해서 쓰는 이유가 분명하게 한다. 학습을 통째로 건너뛰지 못하도록 배틀당 사용 개수를 제한하고, 패스권은 드롭 확률을 낮게 둔다. 패스한 문제는 해설을 보여 주고 오답노트에 남긴다.
4. **실패는 가볍게 처리한다.** 낙제해도 잃는 것이 거의 없다. 학습 게임에서 실패 벌칙이 크면 플레이어가 쉽게 그만둔다.
5. **콘텐츠와 엔진을 분리한다.** 문제 은행만 바꾸면 다른 과목이나 다른 학년용 게임이 되도록 만든다.

## 3. 진행 구조

### 3.1 전체 흐름

```
캠퍼스(허브)
 ├─ 과목 A ── 강의1 → 강의2 → 강의3 → 강의4 → 기말고사 → 이수 ✔
 ├─ 과목 B (선수과목: A) ── …
 ├─ 과목 C (선수과목: A) ── …
 └─ …
모든 과목 이수 → 졸업 엔딩
```

### 3.2 과목 해금

- 과목은 **선수과목** 관계로 해금된다. 예를 들어 "수학 1"을 이수해야 "수학 2"가 열린다.
- 첫 과목은 튜토리얼 역할을 하므로 고정한다. 그다음부터는 해금된 과목 중에서 자유롭게 고를 수 있다.

### 3.3 스테이지(과목) 내부

- 맵은 과목을 테마로 꾸민다. 예를 들어 수학은 기하학 정원, 과학은 실험실 숲, 역사는 옛 거리다.
- 강의는 맵 위에 보이게 고정 배치한다. 이전 강의를 이수하기 전에는 다음 강의로 가는 통로가 막혀 있다. 강의를 이수하면 통로가 열리고, 카메라가 열린 통로를 잠깐 비춰 준다.
- 강의와 강의 사이 공간에는 다음을 둔다.
  - 아이템 상자, 숨은 아이템
  - NPC(조교, 선배): 팁, 서브퀘스트
  - 책더미 구역: 복습 퀴즈가 무작위로 나온다
  - 휴게실: 집중력 회복, 저장
- 마지막 방에서 기말고사를 치른다. 통과하면 과목을 이수하고 캠퍼스로 돌아간다.

### 3.4 재수강

이수한 강의와 기말고사는 다시 도전할 수 있다. 더 높은 성적을 받으면 성적표가 갱신된다. 최고 성적을 노리는 반복 플레이와 업적(§8)의 동기가 된다.

## 4. 퀴즈 배틀

### 4.1 흐름

1. 조우 연출이 나오고 강의가 등장한다. 강의 이름, 레벨, 특성을 보여 준다.
2. 이 강의를 처음 만났다면 개념 카드 1~2장을 보여 준다. 건너뛸 수 있다.
3. 다음 턴을 반복한다.
   1. 문제가 나오고 제한시간이 흐르기 시작한다.
   2. 플레이어는 답을 고르기 전에 아이템을 쓸 수 있다.
   3. 답을 고르면 정답인지 판정한다.
   4. 해설을 보여 준다.
   5. 진도 게이지와 집중력 게이지가 바뀐다.
4. 진도가 100%가 되면 이수(승리)한다. 집중력이 0이 되면 낙제(패배)한다.
5. 결과 화면에 성적(A+~F), 정답률, 최대 콤보, 획득한 경험치, 장학금, 아이템을 보여 준다.

### 4.2 판정과 수치

| 상황 | 결과 |
|---|---|
| 정답 | 진도 증가 = 지력 × 난이도 배수 × 콤보 × 속답 보너스 × 치명타 × 아이템 배율 |
| 오답 | 집중력 감소 = 강의 공격력 |
| 시간 초과 | 오답과 같다 |
| 패스(아이템) | 정답으로 처리한다. 진도가 오르고 콤보가 이어진다. 속답 보너스와 치명타는 붙지 않는다 |

| 계수 | 값 |
|---|---|
| 난이도 배수 | 쉬움 1.0 / 보통 1.2 / 어려움 1.5 |
| 콤보 | 연속 정답마다 +10%, 최대 +50%. 오답이면 초기화 |
| 속답 보너스 | 제한시간의 절반 안에 맞히면 ×1.2 |
| 치명타 | 통찰에 비례한 확률로 ×1.5 |

**수치 예시 (초기값, 밸런스 조정 대상)**

- 강의 분량(진도 100%에 필요한 양) 120, 플레이어 지력 20이면 보통 문제 하나에 24 → 5문제를 맞히면 이수한다.
- 레벨 10에서 지력 47이면 하나에 약 56 → 3문제면 이수한다.
- 집중력 50, 강의 공격력 15면 네 번 틀리면 낙제한다.
- **밸런스 목표**: 적정 레벨에서 강의 하나는 5~6문제, 1~2분 안에 끝난다.

### 4.3 성적

- 정답률 = 정답 수 ÷ 출제 수. 패스는 정답으로, 시간 초과는 오답으로 센다.
- 힌트 아이템은 성적에 영향이 없다. 힌트는 학습 도구이기 때문이다.

| 성적 | 정답률 |
|---|---|
| A+ | 100% |
| A | 85% 이상 |
| B | 70% 이상 |
| C | 55% 이상 |
| D | 55% 미만 (진도 100%를 채웠다면 이수는 인정) |
| F | 낙제 (집중력 0) |

### 4.4 문제 유형

| 유형 | 단계 | 비고 |
|---|---|---|
| 4지선다 | 1차 | 키보드 1~4 또는 클릭·터치 |
| O/X | 1차 | |
| 빈칸 채우기 (선택지형) | 2차 | 4지선다 UI 재사용 |
| 순서 맞추기 | 2차 | 드래그 또는 차례대로 선택 |
| 단답형 | 2차 | DOM 입력창 사용. 한글 IME 때문에 캔버스로는 입력을 받지 않는다 |

### 4.5 출제 규칙

- 강의마다 문제 풀이 있다. 한 배틀 안에서는 같은 문제를 다시 내지 않는다.
- 아직 본 적 없는 문제를 우선 출제한다(가중치).
- 선택지 순서는 매번 섞는다.
- 강의 레벨에 따라 난이도 분포를 정한다. 예를 들어 레벨 1 강의는 쉬움 70%, 보통 30%다.
- 강의 하나의 문제 풀은 **최소 12문제**를 둔다. 한 배틀에 최대 10문제가 나올 수 있고, 재수강할 때도 문제가 다양해야 하기 때문이다.

### 4.6 강의 특성

몬스터마다 개성이 있듯이 강의에도 특성을 붙인다. 강의 데이터에 특성 ID를 나열하면 적용된다.

| 특성 | 효과 |
|---|---|
| 속사포 | 제한시간 −30% |
| 졸음 유발 | 매 턴 집중력 −2 |
| 깜짝 퀴즈 | 일정 확률로 어려운 문제가 두 개 연속 나온다 |
| 친절함 | 첫 번째 오답은 피해가 없다 |
| 앙코르 | 진도 100% 직후 보너스 문제가 하나 나온다. 맞히면 추가 보상 |
| 필기 금지 | 아이템 사용 불가 (기말고사 전용) |

### 4.7 기말고사 (보스)

- 그 과목의 모든 강의 문제 풀과 기말고사 전용 문제에서 출제한다.
- 두 단계로 진행한다. 진도가 50%를 넘으면 2단계로 바뀌고, 어려운 문제 비중이 늘고 제한시간이 줄어든다. 단계가 바뀔 때 연출을 넣는다.
- 아이템은 배틀 전체에서 1개만 쓸 수 있다.
- 통과하면 과목 이수다.

### 4.8 낙제

- 집중력이 0이 되면 "깜빡 졸아 버렸다…" 연출 후 마지막으로 들른 휴게실로 돌아간다. 집중력은 50% 회복된 상태다.
- 잃는 것은 그 배틀의 진행 상황뿐이다. 이미 쓴 아이템은 돌려주지 않는다.
- 틀린 문제는 오답노트에 기록된다.

### 4.9 역질문 턴

플레이어가 강의에게 문제를 내는 턴이다. **강의가 낸 답을 플레이어가 채점**하게 해서, 공격하는 턴에도 실력이 필요하게 만든다. 남을 가르치거나 답을 검토하면 더 잘 배운다는 점도 살린다.

**흐름**

1. 강의 질문 2턴이 지나면 역질문 턴이 온다. 기본 리듬은 질문, 질문, 역질문의 반복이다. 첫 배틀에서도 바로 보이도록 고정 리듬으로 한다.
2. 플레이어가 문제 카드 3장 중 하나를 고른다. 카드는 쉬움, 보통, 어려움이고 카드에는 문제가 보인다.
3. 강의가 답을 말한다. "정답은 ③번이지!"처럼 자신 있게 말하는 연출을 넣는다.
4. 플레이어가 강의의 답이 맞았는지 틀렸는지 O/X로 채점한다. 제한시간이 있다.
5. 결과를 판정하고 해설을 보여 준다.

**판정**

| 강의의 답 | 플레이어의 채점 | 결과 |
|---|---|---|
| 틀림 | 틀렸다고 채점 | **지적 성공.** 진도 대량 증가 (정답 진도 × 1.5 × 난이도 배수) |
| 맞음 | 맞았다고 채점 | 인정. 진도 소량 증가 (정답 진도 × 0.5) |
| 틀림 | 맞았다고 채점 | 속았다. 집중력 피해 |
| 맞음 | 틀렸다고 채점 | 억지 지적. 집중력 피해 |

**강의가 틀릴 확률**

| 카드 | 강의가 틀릴 확률 | 의도 |
|---|---|---|
| 쉬움 | 20% | 대부분 맞힌다. 채점이 쉬워 안전하지만 보상이 작다 |
| 보통 | 45% | |
| 어려움 | 70% | 자주 틀려서 큰 진도를 노릴 수 있다. 대신 플레이어도 정답을 알아야 제대로 채점할 수 있다 |

- 강의 레벨이 플레이어보다 높으면 틀릴 확률이 조금 낮아진다.
- 강의가 틀릴 때는 무작위 오답이 아니라 **그럴듯한 오답**을 고른다. 예를 들어 분수 덧셈이면 분자끼리, 분모끼리 더한 답을 고른다. 문제 생성기가 흔한 실수 유형을 오답 선택지로 만들고, 강의는 그중에서 고른다.
- 역질문 턴에는 아이템을 쓸 수 없다.
- 업적 예시: "날카로운 지적"(역질문으로 지적 성공 10회)

## 5. 아이템과 장비

### 5.1 배틀 아이템

| 아이템 | 분류 | 효과 |
|---|---|---|
| 형광펜 | 힌트 | 오답 선택지 1개를 지운다 |
| 요점 메모 | 힌트 | 문제의 힌트 문구를 보여 준다 |
| 족보 | 힌트 | 오답 선택지 2개를 지운다 (희귀) |
| 패스권 | 패스 | 문제를 정답으로 처리하고 해설을 보여 준다. 오답노트에 기록 (드롭 확률 낮음) |
| 에너지 드링크 | 점수 | 다음 정답의 진도 ×2 |
| 아메리카노 | 점수 | 3턴 동안 진도 ×1.5 |
| 모래시계 | 시간 | 이번 문제 제한시간 +10초 |
| 초콜릿 | 회복 | 집중력 30 회복 |
| 보험 노트 | 보호 | 다음 오답 1회의 피해를 없애고 콤보를 유지한다 |

### 5.2 사용 규칙

- 답을 고르기 전에 쓴다. 아이템을 써도 턴은 넘어가지 않는다.
- 한 문제에 여러 개를 써도 되지만, **배틀당 사용 개수는 3개로 제한**한다. 가방 장비로 늘릴 수 있다. 기말고사는 1개다.
- 패스한 문제는 정답으로 계산한다. 대신 패스권은 상자와 드롭에서 다른 아이템보다 드물게 나온다.

### 5.3 획득 경로

| 경로 | 설명 |
|---|---|
| 필드 아이템 상자 | 맵에 고정 배치, 한 번만 열린다 |
| 숨은 아이템 | 반짝이는 타일을 조사하면 얻는다 |
| 강의 드롭 | 강의마다 드롭 테이블이 있다. 성적이 높을수록 확률이 오른다 |
| 매점 | 장학금으로 산다 |
| 서브퀘스트 | NPC 의뢰를 완료하면 받는다 |

### 5.4 장비

슬롯은 네 개다.

| 슬롯 | 예시 | 효과 |
|---|---|---|
| 필기구 | 4색 볼펜 | 지력 +5 |
| 안경 | 돋보기 안경 | 통찰 +3 |
| 가방 | 큰 백팩 | 배틀당 아이템 사용 +1 |
| 장신구 | 손목시계 | 순발력 +5 |

## 6. 캐릭터와 성장

### 6.1 능력치

| 능력치 | 의미 | 영향 |
|---|---|---|
| 집중력 | HP | 몇 번까지 틀려도 버티는가 |
| 지력 | 공격력 | 정답 하나당 진도 → 이수에 필요한 문제 수 |
| 순발력 | 시간 | 제한시간 = 문제 기본 시간 × (1 + 순발력 × 1%) |
| 통찰 | 행운 | 치명타 확률(통찰 × 0.5%), 낮은 확률로 형광펜 효과 자동 발동(통찰 × 0.2%) |

초기값은 집중력 50, 지력 20, 순발력 10, 통찰 10이다.

### 6.2 레벨업

- 경험치는 강의 이수, 복습 퀴즈, 서브퀘스트, 업적에서 얻는다.
- 레벨이 오르면 집중력 +5, 지력 +3이 자동으로 오르고, **자유 배분 포인트 3**을 받는다. 포인트를 어디에 쓰느냐에 따라 캐릭터 성향이 달라진다(실수에 강한 캐릭터, 빨리 끝내는 캐릭터 등).
- 강의를 순서대로 이수하면 기말고사 즈음 적정 레벨이 되도록 맞춘다. 부족하면 복습 퀴즈로 채울 수 있다.
- 플레이어 레벨이 강의 레벨보다 5 이상 높으면 그 강의에서 얻는 경험치를 줄인다. 쉬운 강의만 반복하는 걸 막기 위해서다.

### 6.3 과목 이수 패시브

과목을 이수하면 영구 패시브 능력을 얻는다. 다음 과목을 고를 때 전략적 이유가 생긴다.

| 이수 과목 (예시) | 패시브 | 효과 |
|---|---|---|
| 수학 | 논리력 | 오답 피해 −10% |
| 영어 | 속독 | 모든 문제 제한시간 +2초 |
| 과학 | 관찰력 | 배틀 시작 시 형광펜 1회 무료 |
| 역사 | 암기력 | 오답노트 문제를 맞히면 경험치 ×2 |

### 6.4 칭호

업적을 달성하면 칭호를 얻는다. 칭호 하나를 골라 장착하면 캐릭터 이름 옆에 표시된다. 칭호는 꾸미기 요소이고 능력치에는 영향이 없다.

### 6.5 캐릭터 생성

게임 시작 시 이름을 정하고 외형 프리셋 4종 중 하나를 고른다.

## 7. 보상

### 7.1 강의 이수 (배틀 승리)

| 보상 | 내용 |
|---|---|
| 경험치 | 강의 기본 경험치 × 성적 배수 |
| 장학금 | 강의 기본 장학금 × 성적 배수 |
| 아이템 | 드롭 테이블에서 1회 굴림. 성적이 A 이상이면 한 번 더 굴린다 |
| 첫 이수 보너스 | 처음 이수할 때만 주는 고정 보상 |

성적 배수는 A+ 1.5, A 1.3, B 1.1, C와 D 1.0이다.

### 7.2 과목 이수 (스테이지 완료)

- 이수증 (성적표에 기록, 과목 평점 계산)
- 과목 패시브 (§6.3)
- 장비 1개
- 많은 양의 경험치와 장학금
- 다음 과목 해금

### 7.3 복습 퀴즈

- 적은 양의 경험치를 준다.
- 오답노트 문제를 맞히면 경험치를 더 준다.

## 8. 업적

### 8.1 분류와 예시

| 분류 | 업적 예시 |
|---|---|
| 진행 | 첫 강의 이수, 첫 과목 이수, 졸업 |
| 실력 | 10문제 연속 정답, 힌트 없이 기말고사 통과, 한 과목 전 강의 A+ |
| 속도 | 5초 안에 정답 20회 |
| 탐험 | 한 과목의 숨은 아이템 모두 발견 |
| 학습 | 오답노트 문제 50개 정복 |
| 수집 | 장비 전 종류 수집 |
| 숨김 | **벼락치기**: 집중력 10% 이하로 기말고사 통과 |

### 8.2 동작 방식

- 게임에서 일어나는 일(정답, 오답, 아이템 사용, 강의 이수 등)은 이벤트 버스로 알린다.
- 통계 추적기가 이벤트를 받아 누적 카운터(총 정답 수, 최대 연속 정답 등)를 갱신한다.
- 업적은 데이터로 정의한다. 단순한 업적은 카운터 임계값으로, 복잡한 업적은 특정 이벤트와 판정 함수로 정의한다.

```js
// data/achievements.js
export const ACHIEVEMENTS = [
  { id: 'streak10', name: '물 흐르듯', desc: '10문제 연속 정답',
    stat: 'streakMax', gte: 10, reward: { title: '물 흐르듯' } },
  { id: 'cram', name: '벼락치기', desc: '집중력 10% 이하로 기말고사 통과', hidden: true,
    on: 'finalPassed', check: (e) => e.focusRatio <= 0.1, reward: { money: 500 } },
];
```

- 달성하면 화면 구석에 알림을 띄운다. 업적 메뉴에서 진행도 막대를 보여 준다.
- 보상은 칭호, 장학금, 일부 장비다.

## 10. 필드

### 10.1 공통

- 16×16px 타일 그리드 위에서 4방향으로 이동한다. 입력은 칸 단위로 받고, 한 칸 이동은 8프레임에 걸쳐 보간한다.
- Shift를 누르고 있으면 두 배 속도로 달린다.
- 바라보는 칸의 NPC, 표지판, 상자를 확인 키로 조사한다.
- 타일 속성: 바닥, 벽, 책더미(복습 퀴즈), 잠긴 통로, 워프(문·출구)
- 카메라는 플레이어를 중심에 두고, 맵 가장자리에서는 멈춘다.

### 10.2 캠퍼스 (허브)

| 장소 | 기능 |
|---|---|
| 과목관 입구 | 각 과목 스테이지로 들어간다. 잠긴 과목은 선수과목을 안내한다 |
| 기숙사 | 집중력 회복, 저장 |
| 매점 | 아이템과 장비 구매 |
| 게시판 | 업적 목록, 성적표 |

### 10.3 강의 몬스터

- 맵 위에 보이게 배치하고, 제자리에서 움직이는 애니메이션을 준다.
- 플레이어가 부딪히거나 조사하면 배틀이 시작된다.
- 이수한 강의는 "이수 완료" 표식으로 바뀐다. 조사하면 재수강할 수 있다.

### 10.4 복습 퀴즈 조우

- 책더미 타일에 들어설 때마다 판정한다. 기본 확률은 10%다.
- 조우가 끝난 뒤 3걸음 동안은 조우가 일어나지 않는다.
- 이수한 강의가 하나도 없으면 조우가 일어나지 않는다.

## 11. 화면 설계

**렌더링을 두 층으로 나눈다.**

- **Canvas 층**: 필드, 캐릭터, 강의 몬스터, 배틀 연출. 내부 해상도 320×180(16:9)을 정수배로 확대하고 `image-rendering: pixelated`로 픽셀을 선명하게 유지한다.
- **DOM 층**: 문제, 선택지, 해설, 대화창, 메뉴, 알림. 캔버스 위에 겹쳐 놓는다.

문제 텍스트는 길고 한글이라서, 저해상도 픽셀 캔버스에 그리면 읽기 어렵다. DOM으로 그리면 글자가 선명하고, 화면 크기에 맞춰 줄바꿈되고, 단답형 입력창과 스크린 리더도 그대로 쓸 수 있다. 폰트는 메뉴 같은 장식 UI에는 한글 픽셀 폰트(Galmuri 등)를, 문제와 해설처럼 긴 글에는 가독성 좋은 폰트(Pretendard 등)를 쓴다. 두 폰트 모두 적용 전에 라이선스를 확인한다.

```

│                                                     │
│        (주인공)                 (분수 슬라임)        │  ← Canvas
│                                                     │
│ 집중력 ████████░░ 40/50     콤보 ×3     ⏱ 12초      │
├─────────────────────────────────────────────────────┤
│ Q4. 1/2 + 1/3 = ?                                   │
│                                                     │

```

## 12. 아키텍처

### 12.1 원칙

1. **로직과 표현을 분리한다.** 퀴즈 배틀 엔진은 화면을 전혀 모르는 순수 로직이다. 행동 결과를 이벤트 배열로 돌려주고, 배틀 씬이 그 배열을 순서대로 연출한다. 덕분에 엔진을 node에서 따로 테스트할 수 있다.
2. **데이터 주도로 만든다.** 과목, 강의, 문제, 아이템, 장비, 업적, 맵은 전부 `data/`에 데이터로 정의한다.
3. **씬 스택을 쓴다.** 필드 위에 대화창, 메뉴, 배틀을 쌓는다. 입력은 맨 위 씬만 받는다.
4. **입력을 추상화한다.** 키 코드 대신 `up / down / left / right / confirm / cancel / menu / choice1~4` 같은 행동 단위로 받는다.
5. **이벤트 버스로 시스템을 느슨하게 연결한다.** 업적, 통계, 오답노트는 게임 이벤트를 구독만 한다. 배틀 코드가 업적 코드를 직접 부르지 않는다.

### 12.3 퀴즈 배틀 엔진 인터페이스

```js
const engine = new QuizBattleEngine({ player, lecture, pool, kind: 'lecture', rng });
// kind: 'lecture' | 'review' | 'final'

engine.start();
// → [{ t: 'intro', lecture }, { t: 'question', q, timeLimitMs }]

engine.useItem('highlighter');
// → [{ t: 'eliminate', choices: [2] }]

engine.answer(1, 6400);   // 고른 선택지, 걸린 시간(ms)
// → [{ t: 'correct', fast: false, crit: false },
//    { t: 'progress', amount: 24, total: 72 },
//    { t: 'explain', text: '...' },
//    { t: 'question', q, timeLimitMs }]

engine.timeout();
// → [{ t: 'timeout' }, { t: 'damage', amount: 15, focusAfter: 25 }, ...]

// 배틀 종료 시
// → { t: 'end', result: 'pass', grade: 'A', rewards: { exp, money, items } }
```

- 제한시간은 실시간이므로 씬이 관리하고, 엔진에는 걸린 시간만 넘긴다. 엔진은 시간을 직접 재지 않아서 테스트하기 쉽다.
- 난수는 `rng` 함수로 주입한다. 테스트에서는 고정 시드를 쓴다.

### 12.4 스크립트(이벤트) 시스템

NPC, 표지판, 서브퀘스트는 명령 배열로 적는다.

```js
script: [
  { if: 'quest.lostNote.done',
    then: [{ say: '노트 찾아 줘서 고마워!' }],
    else: [
      { say: '내 필기 노트를 잃어버렸어… 책더미 근처에서 본 것 같은데.' },
      { setFlag: 'quest.lostNote.started' },
    ] },
]
```

- 명령: `say`, `choice`, `if`, `setFlag`, `give`, `heal`, `battle`, `warp`, `unlock`, `shop`, `wait`, `sound`
- 인터프리터는 `async/await`로 구현한다. `await dialog(text)`는 대화창 씬을 쌓고, 그 씬이 닫힐 때 resolve된다.

### 12.5 상태 모델

```js
state = {
  version: 1,
  profile:  { name: '새내기', look: 0, title: null },
  char:     { level: 1, exp: 0, focus: 50, statPoints: 0,
              alloc: { focus: 0, int: 0, spd: 0, ins: 0 } },
  equip:    { pen: null, glasses: null, bag: null, acc: null },
  bag:      { highlighter: 3, pass: 1, energy: 1 },
  money:    0,
  location: { mapId: 'campus', x: 10, y: 8, facing: 'down', lastRest: 'campus-dorm' },
  courses:  {
    math: { completed: false, final: null,
            lectures: { 'math-1': { best: 'A', clears: 2 } } },
  },
  wrongNote:    { 'math-frac-03': { wrong: 2, streak: 0 } },
  seen:         { 'math-frac-03': 3 },          // 문제별 출제 횟수
  stats:        { correctTotal: 0, streakMax: 0, fastAnswers: 0, itemsUsed: 0 },
  achievements: { streak10: 1762483200000 },    // 달성 시각
```

- 능력치 최종값은 저장하지 않고 레벨, 배분 포인트, 장비, 패시브로 그때그때 계산한다. 밸런스를 바꾸면 기존 저장에도 바로 반영된다.
- localStorage 한 슬롯에 저장한다. `version`이 맞지 않으면 새 게임으로 시작한다. 접근은 try/catch로 감싼다.
- 저장 데이터를 JSON 파일로 **내보내기/가져오기**할 수 있게 한다. 브라우저 데이터를 지우면 진행이 날아가는 문제를 막는다.

- 유형별 선택지 개수 (4지선다는 4개, O/X는 2개)
- `explain` 누락
- 강의별 문제 풀이 12개 이상인지
- 강의별 난이도 분포

## 14. 범위

### 14.1 1차 버전 (수직 슬라이스)

모든 핵심 시스템이 동작하는 최소 분량이다.

- 캠퍼스 허브 1개
- 과목 2개 × (강의 4개 + 기말고사 1개)
- 문제 약 120개 (강의 10개 × 12문제)
- 아이템 6종 이상, 장비 8종 이상
- 캐릭터 생성, 레벨업, 능력치 배분, 장비, 패시브
- 강의 특성 4종 이상
- 오답노트, 복습 퀴즈, 성적표
- 업적 20개
- 매점, 저장(내보내기/가져오기 포함)
- 졸업 엔딩 (1차 버전에서는 2과목 이수 시)
- 디버그 모드

### 14.2 2차 버전

- 과목 추가 (총 4~5개)
- 서브퀘스트
- 문제 유형 확장 (빈칸, 순서, 단답형)
- 사운드와 화면 전환 연출
- 모바일 터치 패드

### 14.3 확장 아이디어

| 아이디어 | 설명 | 필요 조건 |
|---|---|---|
| 문제집 가져오기 | 선생님이나 학습자가 CSV·JSON 문제집을 넣으면 새 과목이 생긴다 | 없음 (클라이언트만으로 가능) |
| AI 문제 생성 | 개념 카드를 바탕으로 문제를 자동 생성 | 서버 필요 (API 키를 클라이언트에 둘 수 없다), 생성 문제 검수 필요 |
| 학습 리포트 | 성적표와 오답 경향을 PDF나 이미지로 내보내기 | 없음 |
| 랭킹 | 과목별 최고 점수 순위 | 서버 필요 |

### 14.4 하지 않는 것

멀티플레이, 다중 세이브 슬롯, 맵 에디터

|---|---|
| 문제 작성이 가장 큰 작업이다 | 문제 포맷을 먼저 고정하고 검증 스크립트를 만든다. 스프레드시트에서 JSON으로 변환한다. 규칙 기반 과목은 문제 생성기를 쓴다 |
| 정답이 틀린 문제가 섞이면 신뢰가 떨어진다 | 검증 스크립트로 형식 오류를 잡고, 해설을 필수로 해서 작성 단계에서 한 번 더 확인하게 한다 |
| 레벨이 너무 강하면 퀴즈가 의미 없고, 너무 약하면 반복 노가다가 된다 | §2 원칙 1을 지킨다. 능력치 효과에 상한을 두고, 레벨 차이에 따라 경험치를 보정한다 |
| 아이템으로 문제를 피해 간다 | 배틀당 사용 제한, 패스권 드롭 확률 낮춤, 패스한 문제도 해설 표시와 오답노트 기록 |
| 같은 문제가 반복되어 지루하다 | 문제 풀 최소 12개, 처음 보는 문제 우선, 선택지 섞기 |
| 긴 문제 텍스트를 읽기 어렵다 | 텍스트 UI는 DOM으로 그리고 가독 폰트를 쓴다 |
| 브라우저 데이터를 지우면 진행이 사라진다 | 저장 내보내기/가져오기 |
| 원작과 지나치게 비슷하다 | 테마, 고유명사, 그래픽, 음악, 대사를 모두 새로 만든다. 핵심 배틀이 퀴즈라서 원작과 구조적으로 이미 다르다 |
